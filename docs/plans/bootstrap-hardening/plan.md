### Eval Runner Does Not Persist Per-Eval Artifacts

`agent-evals.sh` runs each eval and classifies exit codes, but it only prints output to the terminal.

<!-- current-code path=scripts/agent-evals.sh lines=187-225 ref=fb5ce62 region_sha256=7052e5dcd7de4f936a5b93da849b0c697e3a0e91c6ddfc3217e924abb63da193 -->
```bash
for eval_script in "${evals[@]}"; do
  if [ ! -x "$eval_script" ]; then
    printf 'SKIP: %s is not present or not executable.\n' "$eval_script"
    skipped=$((skipped + 1))
    continue
  fi

  printf '\n>>> %s\n' "$eval_script"
  set +e
  # Pass AGENT_LLM_PROVIDER so run_llm inside the eval dispatches to the
  # right provider. Continue passing CLAUDE_BIN for back-compat (eval
  # scripts that read it directly) and add CODEX_BIN for symmetry. The
  # provider-resolved $bin is reflected back into the matching env var so
  # an explicit --provider flag override is honored even if the user only
  # set the OTHER provider's BIN.
  if [ "$provider" = "claude" ]; then
    AGENT_LLM_PROVIDER="$provider" CLAUDE_BIN="$bin" \
      CODEX_BIN="${CODEX_BIN:-codex}" \
      EVAL_TIMEOUT="$timeout_seconds" EVAL_VERBOSE="$verbose" "$eval_script"
  else
    AGENT_LLM_PROVIDER="$provider" CODEX_BIN="$bin" \
      CLAUDE_BIN="${CLAUDE_BIN:-claude}" \
      EVAL_TIMEOUT="$timeout_seconds" EVAL_VERBOSE="$verbose" "$eval_script"
  fi
  rc=$?
  set -e
  case "$rc" in
    0)
      printf 'PASS: %s\n' "$eval_script"
      ;;
    77)
      printf 'SKIP: %s (see eval output above for reason; common causes: %s CLI unavailable, quota/auth, or eval is provider-incompatible)\n' "$eval_script" "$provider"
      skipped=$((skipped + 1))
      ;;
    *)
      printf 'FAIL: %s\n' "$eval_script" >&2
      failures=$((failures + 1))
      ;;
  esac
```

<!-- current-code path=scripts/agent-sync.py lines=248-267 ref=fb5ce62 region_sha256=732e66d50faf3e1f05951494390b8d4452dc84e5a936761aa93783f6c32c5730 -->

def expand_file_entries(template_root, migration, include_adapters, manifest):
    entries = []
    managed_scopes = []
    adapter_report = []

    def add_entry(source_path, target_path, source_kind):
        target_path = rel_path(target_path)
        if target_path in {e["target"] for e in entries}:
            raise UsageError(f"multiple migration entries map to target path: {target_path}")
        entries.append({"source": source_path, "target": target_path, "kind": source_kind})

    for item in migration.get("safe_overwrite", []):
        if "source_glob" in item:
            target_dir = rel_path(item["target_dir"])
            managed_scopes.append((target_dir, None))

                add_entry(source_path, str(Path(target_dir) / Path(source_path).name), "safe_overwrite")
        else:
            add_entry(rel_path(item["source"]), rel_path(item["target"]), "safe_overwrite")

## Implementation Plan

### PR-1: Safe Bootstrap Rendering

- Add `scripts/lib/render_template.py` using Python stdlib only.
- Pass token data from shell to Python through `mktemp -t agent-render.XXXXXX.json` and remove it through a shell `trap` before exit.
- Replace `escape_sed_replacement`, `replace_token`, and the final placeholder `sed -i -E` pass with one Python render call per file.
- Preserve existing bootstrap feature selection, copy layout, adapter generation, and `not configured` fallback text.
- Add `scripts/lib/test_render_template.py` and a deterministic bootstrap fixture test.
- Document `python3` as required for bootstrap, matching the existing sync and plan-validator dependency posture.

### PR-2: Source CI And Generated-Repo CI Example

- Add `.github/workflows/ci.yml` for the template source.
- Run CI on `ubuntu-latest` with Python `3.11`; do not add a macOS job in this series.
- Execute shell syntax checks, template validation, plan-validator unit tests, provider helper tests, deterministic fast evals, and migration fixtures.
- Add `core/github/agent-template-ci.example.yml` for generated repos.
- Document advisory LLM behavior evals as manual, credentialed runs outside default CI.

### PR-3: Eval Artifact Persistence

- Add `--artifact-dir <path>` and `EVAL_ARTIFACT_DIR` support to `scripts/agent-evals.sh`.
- Resolve artifact destination by CLI precedence: `--artifact-dir` wins over `EVAL_ARTIFACT_DIR`; if neither is set, no artifacts are written.
- Write per-eval `metadata.json`, `output.txt`, and prompt snapshots when the helper has prompt text.
- Use classification enum values `PASS`, `SKIP`, and `FAIL`, mapped to exit `0`, exit `77`, and any other non-zero exit.
- Redact metadata values for keys matching `*_TOKEN`, `*_KEY`, `*_SECRET`, `*_PASSWORD`, `CLAUDE_*`, `CODEX_*`, and `OPENAI_*`.
- Keep artifact capture opt-in locally and upload artifacts in CI only when a deterministic job fails.
- Cap one eval run's artifact directory at 20 MiB by refusing additional writes after the cap and recording `artifact_truncated: true`.

### PR-4: Secret Scanning Gate Path

- Add `core/skills/no-secret-leakage/SKILL.md`.
- Update `core/skills/README.md`, skill-count assertions, and full-harness fixture expectations for the eighth skill.
- Update `scripts/agent-eval.template.sh security)` to probe `gitleaks version` and use the installed version's recommended filesystem scan mode, preferring `gitleaks dir .` when available.
- Keep missing `gitleaks` as a `not configured` security scan, not a success.
- Update `core/gates.template.md`, `core/rulebase.template.md`, and docs to distinguish policy ("do not edit secrets") from scanning.

### PR-5: Language Gate Discovery

- Add `scripts/lib/gate_discovery.py` using Python stdlib only.
- Add `scripts/agent-gate-discover.sh` wrapper.
- Implement parsers for Node package scripts, Python project config markers, Go, Rust, Maven/Gradle, Make, Just, Taskfile, and GitHub Actions evidence.
- Emit JSON candidates only, with fields `status`, `gate`, `command`, `evidence_file`, `evidence_key`, `confidence`, and `notes`.
- Add `--write-suggestions` and write `.agent/gate-suggestions.json`; do not modify `.agent/gates.md`.
- When `.agent/` is absent, stdout discovery still works; `--write-suggestions` exits `2` with a clear message because there is no canonical generated-agent root to write into.
- Update bootstrap-pending guidance so agents promote candidates only after reviewing evidence.

### PR-6: Plan Validator Strangler Refactor

## Risks

- Risk: Python renderer dependency blocks first bootstrap on systems without `python3`. Mitigation: fail early with a clear message and document that Python is already required by sync and plan validation.
- Risk: CI runtime grows after migration fixture coverage. Mitigation: keep the default matrix to `ubuntu-latest` and Python `3.11` in this series.
- Risk: Eval artifacts can leak sensitive prompts or outputs. Mitigation: keep artifacts opt-in, redact metadata, avoid hidden-file capture, and document that behavior eval artifacts may contain model output.
- Risk: Secret scanner command changes across `gitleaks` versions. Mitigation: probe `gitleaks version`, prefer `gitleaks dir .` when supported, and cover command choice with a mock fixture.
- Risk: Gate suggestions are mistaken for configured gates. Mitigation: write `status: candidate`, store suggestions separately in `.agent/gate-suggestions.json`, and never write `.agent/gates.md`.
- Risk: PR-6 touches the validator and can obscure behavior drift. Mitigation: add golden output tests before moving code and keep the wrapper path stable.
- Risk: PR-7 output changes break scripts that parse `agent-validate.sh` text. Mitigation: preserve default human summary and add structured JSON as an explicit format.
